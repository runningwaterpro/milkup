# 领域文档（Domain Docs）

工程技能在探索代码前，按下面的规则消费本仓库的领域文档。

## 探索前先读这些

- 仓库根的 **`CONTEXT.md`**；
- **`docs/adr/`** 里与你即将动工的领域相关的 ADR。

这些文件不存在时**静默继续**。不要提示缺失，也不要预先建议创建。`/domain-modeling` 会在术语或决策真正确定下来的时候，惰性地创建它们。

## 文件结构

本仓库是单上下文（single-context）：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-yyy.md
└── src/
```

## 用术语表里的说法

输出里出现领域概念时（issue 标题、重构提案、假设、测试名），用 `CONTEXT.md` 定义的术语。不要用术语表明确排除的同义词。

术语表里还没有这个概念，说明两种可能之一：你在自造项目并不使用的说法（换个说法），或者确实有缺口（记下来交给 `/domain-modeling`）。

## ADR 冲突要显式点出

输出与已有 ADR 冲突时，明确写出来，不要静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重开，因为…_
